# AGENTS.md

## User Profile

The user is an aspiring AI-driven developer who is learning how to build software through prompting and collaboration with an AI coding agent.

The user's goal is to describe the desired result, provide feedback, and learn from the completed work while allowing the agent to handle the implementation. Do not require the user to write the code themselves. Explain important decisions in clear, beginner-friendly language so the user can understand how the project works and improve their prompting and development skills.

## Project Context

This repository contains a Frontend Mentor newbie-level project. Treat it as a small learning project and keep the implementation simple, readable, and appropriate for a beginner.

This file is a reusable template. Do not add instructions that are specific to one challenge or repository.

## Public Repository Safety

This is a public repository. Treat every committed file, code comment, message, and piece of metadata as information that any visitor may read.

- Never commit or publish secrets, credentials, API keys, access tokens, private URLs, personal data, or sensitive configuration.
- Never add private notes, instructions, or comments written specifically for the user that would be inappropriate or confusing for a random public visitor.
- Keep code comments focused on explaining the project and its implementation, not private communication with the user.
- Use ignored local files or environment variables for sensitive values, and provide only safe placeholders in tracked example files.
- Keep the `docs/` directory private and excluded from version control.

## Agent Responsibilities

- Take ownership of the requested development work from start to finish.
- Implement the solution directly when the user asks for a change or feature.
- Make reasonable decisions when details are missing, while staying faithful to the user's intent and the supplied design.
- Inspect the existing files before making changes and preserve unrelated work.
- Explain the result and important choices in plain language after completing the work.
- Verify the implementation whenever practical, including layout, responsiveness, and basic accessibility.
- Keep the project approachable. Prefer clear code over clever or unnecessarily advanced techniques.

## Technology Constraints

- Use only HTML, CSS, and vanilla JavaScript.
- Do not install libraries, frameworks, packages, build tools, or dependencies.
- Do not introduce tools such as React, Vue, Angular, Svelte, Tailwind CSS, Bootstrap, Sass, TypeScript, npm packages, or bundlers.
- Use JavaScript only when the project genuinely needs interactivity.
- Prefer semantic HTML and modern, standards-based CSS.
- Keep all code understandable to someone at the beginning of their frontend development journey.

## Quality Guidelines

- Match the provided design as closely as practical.
- Build responsive layouts that work on both mobile and desktop screens.
- Use semantic HTML elements and a logical heading structure.
- Provide meaningful alternative text for informative images and empty alternative text for decorative images.
- Maintain readable color contrast and visible keyboard focus styles where interactive elements exist.
- Organize CSS clearly and avoid unnecessary repetition.
- Avoid overengineering; choose the smallest solution that fully meets the requirements.
- Test for obvious visual, functional, and accessibility issues before considering the work complete.
